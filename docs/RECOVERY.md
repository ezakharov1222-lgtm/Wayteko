## 4. Шифрование

AES-256-GCM, ключ = PBKDF2-SHA256(пароль, salt, 250 000 итераций, 32 байта). Формат файла: `{"v":1,"iter":250000,"salt":b64,"iv":b64,"ct":b64}`. Копии владельца — главным паролем; копия гостя — паролем гостя; путь гостевой копии = `data/g-` + первые 16 hex от sha256("wayteko-guest:" + пароль гостя) + `.enc.json`. Пароль никогда не попадает в репозиторий, отчёты, письма, память.

## 5. Данные

**Клиент** (коллекция `clients`, id вида c01…): `name`, `temp` (hot 🔥 горячий, warm 🌤 тёплый, cold ❄ холодный, dealer ✅ дилер, branch ↪ филиал, refused ⛔ отказ), `next` (дата созвона ГГГГ-ММ-ДД), `phone`, `fio`, `plan` (следующий шаг), `intro`, `touches` [{d, t}] (касания: дата, итог), `meets` [{id, d, t (время), place, note (цель), done}], `updated` (ISO), прочие поля карточки.

**Задача** (коллекция `tasks`, только владелец): `id`, `d` (дата), `text`, `cid`/`cname` (клиент, необязательно), `owner` (ответственный), `prio` (urgent 🔴 срочно / high 🟠 важно / normal), `done`, `del` (удалена), `created`, `updated`.

**Гость** (в копии владельца, до 4 шт.): `id`, `name`, `pw`, `off`, `updated`.

localStorage приложения: wayteko.clients.v1, wayteko.meta.v1, wayteko.pw.v1, wayteko.gh.v1, wayteko.role.v1, wayteko.guests.v2, wayteko.tasks.v1.

## 6. Функции приложения (всё это должно работать)

1. **Вход**: стартовый экран показывает только форму пароля, без данных. Главный пароль — владелец; пароль гостя (G-XXXX-XXXX-XXXX) — гость.
2. **Вкладки**: Сегодня, Воронка, Все клиенты, Филиал и отказы, Задачи (только владелец), Данные.
3. **Карточка клиента**: статус, созвоны, касания, план, **кнопка «Встреча»** в каждом клиенте и на главном экране; добавление встречи (дата, время, место, цель); **предупреждение за 3 дня** до встречи (баннер на главном и пометка «⚠ через N дн.»).
4. **Синхронизация устройств**: все устройства, где вошли главным паролем, после каждого изменения загружают зашифрованную копию в `data/app.enc.json` через GitHub Contents API (токен fine-grained, коммиты с `[skip ci]`, при 409/422 — повтор) и периодически подтягивают её: слияние по `updated` (новее побеждает), удалённые — «надгробия», задачи и гости сливаются по id. Новое устройство получает токен из общей копии.
5. **Гостевой доступ**: до 4 гостей, у каждого имя и свой пароль (генерируется, кнопка «Скопировать»). Гость видит всё только для просмотра, любые изменения блокируются («Гостевой доступ: только просмотр»). **Задачи гостям не видны и в их копии не попадают.** Отключение гостя — удаляет его копию. Статус «в сети / смотрит» — через ntfy.sh (темы из хэша пароля), виден владельцу.
6. **Задачи** (только владелец): по дням (‹ › Сегодня), клиент (необязательно, с подсказками), текст, **«Ответственный»**, **3 уровня срочности** — срочные яркие красные и всегда сверху, баннер срочных; отметка выполнения, перенос просроченных на сегодня, удаление, счётчик на вкладке.
7. **Данные**: резервная копия JSON (скачать/восстановить, включая задачи), выгрузка Excel, настройка GitHub-токена, управление гостями.
8. **Иконка** WAYTEKO (из src/logo, выровнена по центру) для экрана «Домой» на iPhone. Внимание: на iPhone удаление иконки стирает данные приложения на этом устройстве (общая копия в репозитории остаётся).

**Интернет-версия** (артефакт): та же CRM на базе данных артефакта; вкладка «Задачи» в ней только для чтения, со срочностью. Исходник — `src/vaitek-crm.html`.

## 7. Правила (не нарушать)

- Главный источник — приложение. Интернет-версия получает данные из него каждый вечер; при конфликте берётся более свежая правка.
- **Задачи** попадают в интернет-версию и в резервные копии, но **никогда** — в вечерний отчёт, Excel, гостевые копии и сообщения. Отдельно о задачах — только своё письмо в 20:17.
- Пароль и токен — нигде не показывать, не записывать в файлы репо, отчёты и память.
- Письма — только через Gmail-коннектор (встроенные уведомления на почту ненадёжны).
